# CLI

```text
kashika check   <file|-> [--format text|json] [--stdin-name <name>] [--allow-path] [--include <file>] [--summary]
kashika render  <file|-> -o <out.svg|out.png|out.jpg|out.jpeg|out.webp> [--force] [--debug] [--format text|json] [--stdin-name <name>] [--allow-path] [--include <file>] [--summary]
kashika inspect <file|-> [id ...] [--ports] [--corridors x1,y1,x2,y2] [--format text|json] [--stdin-name <name>] [--allow-path] [--include <file>]
kashika fmt     <file|-> [--check]
kashika measure "<text>"... [--size N] [--weight bold] [--format text|json]
kashika route   <file|-> <from> <to> [corner|arc|bezier] [--line <id>] [--radius N] [--max N] [--format text|json] [--stdin-name <name>] [--allow-path] [--include <file>]
kashika icons   [dir...] [--search <term>] [--format text|json]
kashika ref     [topic] [--json]
kashika --version
```

- `check` and `render` take `--format text|json`, `--fail-on error|warn|never` (default `warn`), `--max N` (diagnostics shown; errors are listed before warnings, every error is always reported and warnings fill the rest; past 1,000 warnings per code, or `--max` if larger, the rest are only counted), `--stdin-name <name>`, `--focus <id,...>` (only warnings naming these ids; errors always show) and `--show-suppressed` (list suppressed findings with their `reason`) and `--summary` (per-code counts, active and suppressed; JSON always carries them as `by_code`).
- Text output escapes control characters and bidirectional overrides from the input (in source lines, messages and names) as `\u{1b}`; JSON keeps the original text.
- `check` on a library (no `diagram`; only `shape`, `style` and `import`) resolves its definitions and reports their errors, with no lints; `--focus` there takes shape names; `render` on one exits 3.
- `render` writes only when there are no errors, atomically; with errors an existing output file is left untouched. `--force` writes anyway, with red markers at each error. `--debug` adds rulers, ids, anchor dots and markers for every diagnostic. PNG and WebP keep the canvas transparent unless `background=` is set; JPEG composites onto white or the `background=` color.
- `inspect` prints resolved geometry (never fails on errors): boxes, groups and images with bbox and anchors (plus the file's natural size, aspect ratio and `fit` for images and `shape from` SVGs), junctions, texts, lines with vertices, authored segments (`line:col`), length and label positions, and the placement graph. Ids limit the output (unknown id: exit 3); `--corridors` without ids prints only the corridors. `inspect` takes no `--fail-on`, `--max`, `--focus` or `--show-suppressed`. Elements inside a group also show local coordinates. `--ports` lists each line endpoint on a shape side. `--corridors` lists the free `y` and `x` intervals in the rectangle. `--format json` writes `kashika.inspect/1`.
- `fmt` changes only whitespace: indentation, spacing and blank lines. Comments and the spelling of numbers and strings are kept. Line endings become LF everywhere, including inside block comments, and a leading byte order mark is dropped. `--check` exits 1 when the file isn't formatted; a parse error exits 2. `fmt -` reads stdin and writes the formatted text to stdout (`--check` on stdin prints nothing but exits 1 when it isn't formatted).
- `measure` prints the exact width and height of each text argument, with markup applied. One text gives one result (JSON: the fields at top level); several give one line each (JSON: a `results` array with each `text`). A markup error exits 2.
- `route` prints up to `--max` (default 3) ready-to-paste `line` statements from `<from>` to `<to>`, ranked by crossings plus group transits (a path through a group it doesn't connect into, `group-transit`, weighs the same as a crossing), then near-misses, segments and length, with ties going to paths whose lanes follow the endpoints' own boxes. Each candidate prints `crossings=N (line at (x,y), …) transits=N (group at (x,y), …) near=N segments=N length=Npx`; JSON has `crossings`/`crossed` and `transits`/`transited`. It never edits the file. Styles: `corner` (`x`/`y`/`hv`/`vh`), `arc` (the same plus `radius=N`, default 8), `bezier` (`curve`). `--line <id>` reroutes an existing line and keeps its attributes; without it, an existing line between the same two shapes counts as an obstacle, and `route` adds a `hint:` line (JSON: `existing_lines`) naming it. `<from>` and `<to>` are single points written as in a `line`; literal points are canvas coordinates. `--format json` is supported. Orthogonal styles try paths with up to 2 elbows and detours with 3 or 4 elbows along lanes beside boxes and groups or through the middle of free corridors (also used by the one-lane paths) (16 lanes per axis nearest the endpoints, the 32 best one-lane paths and 32 best detours scored, none that double back); `bezier` tries single curves. Beyond that, write the path by hand along a lane from `inspect --corridors`.
- Files (`import`, `shape from`, `image`, `icon=`) resolve from the input file's directory (the current directory for stdin), then the `icons=` directory, then each `KASHIKA_ICON_PATH` entry (`:`-separated), then the bundled icons. `check`, `render`, `inspect` and `route` take `--allow-path` to permit references outside the input's directory; without it they report `error[file]`. `--include <file>` (repeatable) permits just that file, given relative to the current directory: `kashika check diagrams/board.kash --include lib/pieces.kash` for `import "../lib/pieces.kash"`. An included library's own relative references resolve from its directory and need their own `--include` (or to be inside the input's directory or on the search path). A `--include` that is missing or a directory exits 3. `KASHIKA_ICON_PATH` entries are always trusted.
- `icons` lists the bundled icons and built-in shapes, then the images and `.kash` shapes under each `dir` (default: the `KASHIKA_ICON_PATH` entries), as `name path size library`. `--search` matches the name, path or a keyword, case-insensitively, so `--search user` finds `person` and `--search database` finds `cylinder` (the text output notes the keyword that matched; user directories have no keywords); with no match it says so on stderr and exits 1. A `dir` that isn't a directory exits 3. Symlinked directories aren't followed. `--format json` returns `{"schema":"kashika.icons/1","icons":[...]}`.
- `ref` prints this reference; `--json` wraps a page as `{"schema":"kashika.ref/1",...}`.
- `--radius` must be a finite number, 0 or more; `route --max` and `--corridors` coordinates are validated (non-finite values exit 3). A JSON tool error (exit 3) carries the command's own schema: `kashika.route/1`, `kashika.inspect/1`, `kashika.measure/1`, `kashika.icons/1`, `kashika.ref/1`, and `kashika.check/1` for check, render and fmt.
- `format` is an alias of `fmt`, and `references` and `docs` are aliases of `ref`.
- Exit codes: `0` clean, `1` warnings (also `fmt --check` with changes, `route` with no path and `icons --search` with no match), `2` errors (also `fmt` on a parse error), `3` usage or I/O failure.
